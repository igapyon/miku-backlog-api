# GitHub Issue Drafts

## 上流MCPハンドラーとNode操作の差分テストを追加する

### 概要

代表的なBacklog操作について、上流MCPで合成されたハンドラーと変換後の
Node操作へ同じ入力とモック応答を与え、結果が一致することを検証します。

### 対応内容

- 読み取り、追加、更新、削除から代表操作を選定する
- 同じBacklogモック応答を両方の実装へ入力する
- 入力変換、API呼び出し、戻り値、エラーの差異を比較する
- 意図したCLI固有差分は理由とともに記録する

### 完了条件

- 代表操作の差分テストが自動実行される
- 意図しない差分をテスト失敗として検出できる

## fields選択とトークン制限のCLI互換性を検討する

### 概要

上流が提供するGraphQL風の`fields`選択とトークン制限を、Node CLIでも
提供すべきか検討します。

### 検討事項

- 上流機能の正確な仕様と適用対象
- JSON CLI利用時の必要性
- 出力形式とトレーサビリティへの影響
- 互換性を追加しない場合の明示的な差分記録

### 完了条件

- CLIへ追加するかを決定する
- 採用時は実装とテスト、非採用時は理由を文書化する

## 利用可能なBacklog組織を列挙するNode操作を検討する

### 概要

上流の`list_organizations`相当を、追跡可能なNodeメタ操作として追加するか
検討します。複数組織環境で現在利用できる接続先を、安全に確認できるように
することが目的です。

### セキュリティ要件

- APIキーを結果へ含めない
- 必要最小限の組織名とドメイン情報だけを返す
- 現在の既定組織を識別できるようにする

### 完了条件

- 操作追加の可否を決定する
- 採用時はCLI、テスト、トレーサビリティ資料を更新する

## 未使用のMCP SDKとHTTP依存をインストール対象から除外する

### 概要

生成runtimeでは除外されているMCP SDKおよびHTTPサーバー関連依存が、上流
パッケージの依存関係としてインストールされます。Node CLIに不要な依存を
導入せずに済む構成を検討します。

### 完了条件

- 現在の依存経路を記録する
- 上流コードとのトレーサビリティを保つ削減方法を決定する
- ビルド、58操作、CLI smoke、ライセンス同梱のテストが成功する

## 実際のBacklog環境で読み取り専用操作を検証する

### 概要

実際のBacklog環境に対して代表的な読み取り専用操作を実行し、設定方法と
結果形式を検証します。

### 安全要件

- 実行前にユーザーの明示許可を得る
- 追加、更新、削除操作を実行しない
- APIキー、組織情報、Issue情報をリポジトリへ保存しない
- 診断結果を共有する場合はテナント情報を伏せる

### 完了条件

- 読み取り専用操作が成功する
- 認証情報や取得データが残存しないことを確認する
